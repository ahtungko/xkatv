# 电视浏览器投屏

## 部署

在已有账号数据库上执行 [202611050001_tv_cast.sql](../supabase/migrations/202611050001_tv_cast.sql)，然后部署新版前端。当前 `schema.sql` 尚未包含此迁移，新项目在整合脚本后也需要执行它。不要在新旧投屏版本之间混用配对码。

功能使用 Supabase RPC，不使用公共广播频道，不要求开启 Supabase 匿名登录，也不需要在前端配置服务端密钥。数据库中的会话、消息和尝试次数表不开放直接客户端访问。电视持有随机临时凭证；手机使用已登录账号及独立会话凭证。仅对应会话双方可收发消息。

## 使用

1. 电视浏览器打开 `/tv`，获得五分钟有效的四位配对码。
2. 手机扫描二维码进入 `/cast`，未登录时先登录；登录后自动发起配对。也可点击全站「连接电视」入口，手动输入四位码。
3. 用电视遥控器选择「允许投屏」。手机显示已连接，电视显示等待选片；这一步不会发送视频，也不会暂停手机播放。
4. 手机正常浏览、搜索、选择视频，在播放器点击「在电视播放」。全站「电视遥控器」入口可暂停、跳转、调整音量或断开连接。
5. 关闭弹窗、离开播放器或切换网站页面不会断开配对。退出账号、手动断开、电视离线或会话过期才结束连接。刷新整个网页或系统回收标签页后需要重新配对。

配对码仅供一次申请，不能作为长期设备书签；电视可以拒绝请求并刷新配对码。每个有效账号一分钟最多尝试五次配对。已确认会话最长六小时，到期需重新配对。

消息每 750 毫秒轮询，电视每 1.5 秒发送进度；控制有网络延迟，不属于屏幕镜像。手机收到电视确认并点击「在电视播放」后才发送媒体，电视忽略同一媒体的重复加载。电视长时间不回传进度或会话失效时，手机提示重新配对。

视频由电视直接加载，因此电视浏览器仍需支持对应编码和跨域请求。首次有声播放可能需要按电视播放键，具体取决于浏览器自动播放策略。匿名配对创建端点应使用 Supabase/网关的流量限制来控制公共请求量；账号尝试限制与电视确认不替代基础设施的防滥用措施。

## 验证

`pnpm exec vitest run scripts/tv-cast-db.test.ts src/features/player/hooks/useTvCast.test.ts` 验证凭证隔离、确认前拒绝媒体、单次配对码、失败次数限制，以及进度回传不触发重复加载。上线后需用实际电视确认遥控器操作、自动播放与编解码兼容性。

## 手机息屏与键盘控制

手机进入后台或息屏时暂停轮询并保留连接，电视独立继续播放；回到前台后恢复查询并留出重连时间。手机后台期间无法可靠执行自动切集等 JavaScript 操作，系统关闭或回收标签页也可能需要重新配对。

电视播放器的空格/Enter 控制播放暂停，左右键跳转 10 秒；手机遥控器支持前后 15 秒跳转。视频时长尚未加载时不执行跳转，避免无效时间。已移除固定时长的跳片头按钮。

本次前端交互调整无需新增 SQL，已有 `202611050001_tv_cast.sql` 仍然适用。部署后同时刷新手机与电视页面。
